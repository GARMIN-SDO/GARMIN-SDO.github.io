## 傳輸量與驗證界線

先前本機 gzip／HTTP cache 的同一手機流程：原版 10.26 MB → 關閉 cacheBust 6.50 MB → 加入無損候選 4.37 MB → Q95 候選 2.03 MB。這是瀏覽器實際 HTTP 傳輸量，與檔案總量不同；不代表 GitHub Pages 上線後的實測，還受獎品、伺服器壓縮和瀏覽器快取影響。候選測試的先鋒圖片也曾使用 Q95，最終採用版已改回原始 PNG。

正式引用替換後，已在本機 Mock 驗證手機單圖、桌機雙圖與先鋒隊版型的圖片、縮圖及 1080×1920 PNG 下載，未發現瀏覽器錯誤或水平溢出。Node 測試通過。Google 端部署與正式傳輸量仍須維護者確認。

## 後端圖片路徑

前端不再轉換舊 PNG URL。Apps Script `Allocation.gs` 的 `getPrizeImagePath()` 直接提供五種現行 WebP URL；新分配、相同 requestId 重播和 `Code.gs` 的 GET 恢復都採用目前獎品 URL。只改回應圖片位置，不重寫歷史 Requests JSON、不扣額外庫存。

`Setup.gs` 的新建工作表預設圖片路徑亦為 WebP。既有 `Prizes`／`DemoPrizes` 圖片欄即使仍是舊 PNG，五種現有獎品的 API 回應會優先使用程式中的 WebP 路徑，無需 migration 或初始化。需要讓表格顯示一致時，可人工將這兩張表的圖片路徑副檔名改為 `.webp`；不更動庫存欄位。
